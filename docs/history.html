2026-11-19

  • P2 slice 4: emission and texture alpha, Godot style. StandardMaterial3D gains emission_enabled, emission (a Color the lit shader adds after lighting, Godot's emission_energy_multiplier in tow), and emission_texture as an RGB mask. The albedo texture's alpha channel now joins the albedo color's alpha — a material whose texture or albedo fades draws blended without any node transparency. SurfaceTool gains add_index, set_material, and get_aabb, Godot's cheap trio. The script editor colors documented lowercase engine globals (load, resource_cached, and every Globals class member) green like a class name, Look up lists every documented member a bare name resolves to (ResourceLoader.load and ProjectSettings.load both answer), and ResourceLoader.load now documents the import idiom — Godot's synchronous load() arrives in Corbel as a Promise because the decode happens off the main thread, with resource_cached(path) as the synchronous cache test.
  • P2 slice 3: texture maps and fog, Godot style. StandardMaterial3D gains normal_texture with normal_scale, roughness_texture and metallic_texture with their TextureChannel channel masks (roughness reads R, metallic reads B, the Godot defaults), uv1_scale and uv1_offset, and vertex_color_use_as_albedo. A normal map tilts shading through the mesh's tangents — BoxMesh now builds tangents on every vertex. Materials carry Godot's render_priority and next_pass. GeometryInstance3D.material_override and transparency move to their Godot home, transparent draws blend after the opaque ones, and MeshInstance3D's geometry property is now Godot's mesh, with set/get_surface_override_material and get_active_material. Mesh grows the real Godot API: multi-surface ArrayMesh (add_surface_from_arrays, surface_remove, clear_surfaces, surface names), get_aabb, get_faces, and the ARRAY/PrimitiveType constants. BoxMesh gains subdivide_width/height/depth. Environment gains the fog block (fog_enabled, fog_mode exponential or depth, fog_light_color, fog_density, fog_depth_begin/end/curve, fog_height, fog_height_density); the WGSL and GLSL shaders share the fog math, camera distance, and height falloff. Verified live on both backends: lit cube with normal and roughness maps, blended transparent slab, and per-pixel fog fading with view distance and thinning with height.
  • Documentation restructured into Godot's shape: ABOUT, GETTING STARTED, MANUAL, ENGINE DETAILS, CLASS REFERENCE, and COMMUNITY sections (community will live on ExoDev.Com). All documentation pages moved into a docs/ folder, and the class reference is now one file per class, Godot style — docs/class_Node.html, docs/class_Node3D.html, and so on for all 44 classes, plus docs/class_reference.html as the "All classes" index grouped Globals/Nodes/Resources/Input/Variant types. Each class page has the Godot format: inheritance chain, brief, description, properties, methods. tools/make-class-docs.mjs regenerates all of them from docs/class_reference.json. The script editor's Look up opens the matching docs/class_*.html page and jumps to the member row.
    • P2 slice 2: material files and the world environment. `load("res://textures/portal.cmaterial")` builds a StandardMaterial3D from JSON (`albedo`, `albedo_texture` — the texture inside loads with it). `WorldEnvironment` + `Environment` set the tree's background (canvas clear color) and ambient; the renderer picks the first WorldEnvironment in the tree. Verified live: the demo game window clears to sky blue `#87ceeb` and level2's portal renders through the material file.
    • P2 started: textures load and render. `Texture2D` decodes project images (PNG/JPG/GIF/WebP through the binary-aware project API and the browser's decoder), `load("res://textures/…")` caches them by path, and `StandardMaterial3D.albedo_texture` multiplies the albedo on WebGPU and WebGL2 (UV plumbed through the vertex format with per-face 0–1 squares on BoxMesh; texture-less materials sample a white 1x1). Demo: the cube shows `brick.png`, level2's portal shows `portal.png` — generated with a small PNG-writer tool.
    • Script-check flagged a phantom error: the language service rejected the project convention of importing scripts by `.ts` extension (`import Score from "./score.ts"` in level2.ts) because `allowImportingTsExtensions` was missing from the editor's checker options — added everywhere, and the checker's `lib` bumped to ES2024 to match the engine (Promise.withResolvers in core signals). The diagnostics panel is now clean for the demo.
    • Errors and warnings copy out of the editor now: Output lines render separately with Ctrl+C selection, a per-line ⧉ copy chip, and a header Copy/Clear pair; game window errors (script load failures, engine errors, import path problems) relay to the editor Output through `window.opener.postMessage`, and the game window shows a "Copy errors" button beside its error overlay. Cause verified in the browser: a relayed error line lands as `ERROR: Import path problem at res://demo/x.ts (2 errors)` in Output and copies.
    • Level switching made real: `change_scene_to_packed` runs the tree's weaver hook (the runtime installs it), so a loaded scene's scripts attach exactly like `change_scene_to_file` — Godot's `PackedScene`-carries-compiled-scripts behavior. The runner also registers the boot scene as `current_scene` so the first swap frees it. Demo: L bounces `Main` ↔ `Level2` in the game window (level2 builds a purple portal from its own script) and the `Score` autoload persists across swaps (points counted per play).
    • P1 finished: `PackedScene` + `load("res://…")` + `change_scene_to_packed`. Scenes save to `.cscene` and load back through a shared `ResourceLoader` (caches by path, custom handlers per extension, pinned across realms), the runner registers the loaded scene as `current_scene` at boot so the first swap frees it, scripts weave into fresh instances, and the demo's `L` bind swaps `Main` → `Level2` with the `Score` autoload surviving. Timers (previous slice) and this make P1 done.
    • Timers, pause modes, and scene change: Godot's `Timer` node (`wait_time`, `one_shot`, `autostart`, `timeout`), `process_mode` with the full pause matrix (PAUSABLE/WHEN_PAUSED/ALWAYS/DISABLED), `Node.get_tree()`, and awaitable signals — `await get_tree().create_timer(0.5).timeout` works even while paused, and `change_scene_to_file` frees the old scene and swaps in the loaded one through the runtime's scene loader.
    • P1 started: Godot's Globals/Autoload and the `class_name` registry. Project scripts register their default export class by its own class name into a shared registry (`create_node("Score")` builds custom types, and the Add menu lists them); Project → Globals — Autoload… manages the autoload list; Play creates each autoload under `/root/<Name>` before the main scene. Verified in the game window: the tree reads `Score (autoload), Main (scene)` and `get_node("/root/Score")` returns the class.
    • Play opens the game in its own window, like Godot. The runner moved to `@corbel/runtime`; `apps/game` is the window page, served by the editor dev server at `/game`, sized from `project.corbel.json`. Play saves the scene first and opens the window; Stop closes it; Pause lands when the window gets a control channel. The window keeps the input lock: game keys while the canvas holds focus.
    • Modifier binds work: an action with Additional Options (Alt, Shift, Ctrl, Windows/Meta) matches only while those keys are held, live — you can press, hold the key, then let the modifier go and the action drops. Two root causes were fixed: the device state now checks the bind's modifiers against the last event's, and a key bind never leaves a stale latched press behind. Key names `Shift`, `Ctrl`, `Alt`, and `Meta` resolved instead of throwing. The game canvas also now locks its input: Space, Alt, and refresh no longer drive the browser page while the game holds the canvas (Devtools stays reachable with F12 or Ctrl+Shift+I/J/C), and right-mouse binds work because the browser menu is suppressed on the canvas.
    • Two input fixes from real use: the run canvas now takes keyboard focus, so binds work without any trick, and the runner actually loaded the project settings (the file endpoint's JSON payload was read raw, so every action list came back empty). The Input Map dialog also works like Godot's now: Add New Action, an Event Configuration popup with Filter by Event, Keyboard Keys and Mouse Buttons groups, Additional Options toggles (Alt, Shift, Ctrl, Windows), a Physical Keycode vs Keycode select with `Space (Physical)` labels, and per-action Deadzone. Events carry both codes — `event.code` for the layout-independent position, `event.key` for the layout key — so layout auto-detection is free.
    • Slice 5: input works. `Key`, `InputEventKey`, `InputEventMouseButton`, `InputEventMouseMotion`, and `InputEventAction` in Godot 4 values; `InputMap` loads named actions from `project.corbel.json`; `Input.is_action_pressed` reads them. Project → Project settings… edits the binds with a key recorder. Play feeds the run canvas's DOM events to the tree, and `player.ts` now spins the cube fast while Space is held through the `spin_fast` bind.
    • Materials load like Godot: `Material`, `ShaderMaterial` with `set_shader_parameter`, and `Shader.lit({ uniforms, webgpu_body, webgl_body })` for one program pair over both backends. The built-in lit material and every user material now go through per-shader pipelines and per-material uniform buffers; the sandbox pyramid draws through a user shader whose `Sides` parameter tints it. The engine draws the pyramid identically on WebGPU and WebGL2.
    • `SurfaceTool` builds meshes in code — `begin(PrimitiveType.TRIANGLES)`, per-vertex `set_normal`/`set_uv`/`set_color`/`set_tangent` (reset after each vertex, like Godot), `index()`, `generate_normals()`, and `generate_tangents()` with UV-driven binormal signs. The sandbox now shows a four-color pyramid built entirely in code beside the BoxMesh cube. The fix underneath: WebGPU draws needed one uniform buffer per draw, because `queue.writeBuffer` calls all land before the submitted pass.
    • Slice 4: `@corbel/react` with `EngineView`, `useSceneTree`, and `useSelection`. The sandbox is a React app: `EngineView` owns the canvas, and the panel reads the live tree node count.
    • `Dictionary`, the Godot key/value map, with `has`, `get_or_add`, `merge`, `duplicate(deep)`, and `find_key`.
    • Play, Pause, and Stop work. The 3D workspace holds a canvas; Play rebuilds the open scene, turns every scripted node into an instance of its script's default export class, and runs it on WebGPU or WebGL2. A throwing _ready or _process prints Player (ready): Node not found: Nope style lines to Output, through SceneTree.on_node_error. Pause skips _process and keeps the frame. A new root tsconfig.json gives the projects scripts the same compiler settings the editor uses.
