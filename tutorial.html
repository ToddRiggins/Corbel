Editor, project, and file type

Use Visual Studio Code. It is free, and it is already installed on this machine. Download it from code.visualstudio.com only if that copy is missing.

The project is the folder C:\Users\exode\Desktop\Corbel. There is no special Corbel project file. In Visual Studio Code choose File → Open Folder and open that folder. Leave it open while you work.

Code is saved as .ts files. That is TypeScript. The file you edit to try an idea is:

packages/try/src/main.ts

Save with Ctrl+S. A second experiment is File → New Text File, then Save As, into packages/try/src, and the name must end in .ts. Docs such as this page stay .html. Do not start new engine code as .js or .gd.

Typos and errors

A typo should show up before you trust a result. There are two reports, and you use both.

While you type, Visual Studio Code draws a red underline. Hover it. On a misspelled Vector3.FORWRD it says the name does not exist, and it asks if you meant FORWARD.

The underline can be missed. The command that lists every one is npm run check. Run it from the terminal after you save. Terminal → New Terminal, in the Corbel folder. A real misspelling prints this:

src/bad.ts(2,19): error TS2551: Property 'FORWRD' does not exist on type 'typeof Vector3'. Did you mean 'FORWARD'?

Read it from the left. src/bad.ts is the file. 2 is the line. 19 is the column. The rest is the mistake. Fix that line, save, and run npm run check again. A clean run prints no line that says error TS.

npm test does a different job. It runs the math checks and names the check that failed. A typo in a file that no test imports can pass npm test and still be wrong. Run npm run check first.

After check is clean, npm run try runs main.ts. Today a good run prints:

Corbel try file is running.
Vector3.FORWARD is 0 0 -1

If the run still crashes, the terminal names the file and the line. That line is the one to read. Check would already have caught a bad name. A crash after a clean check is a value problem, such as dividing by zero, not a misspelled word.

Browser editor

Double-click start_editor.bat in the Corbel folder. It starts the editor and opens http://127.0.0.1:5177/. The same server is npm run editor. The page is dark, with rounded flat docks: Scene and FileSystem on the left, the 3D workspace and Output in the middle, and the Inspector on the right.

The demo project is projects/demo. A scene is a .cscene file. main.cscene is the one that opens. player.ts is the script. The Script workspace colors keywords, types, functions, members, variables, strings, and numbers separately. A− and A+ change the code font. A typo such as Vector3.FORWRD shows under the script, with the file, the line, and “Did you mean FORWARD?”. Help → Documentation opens the reference in a new window. Right-click a documented name in a script and choose Look up. That name sits at the top of the reference.

The Scene dock lists each node by name. The arrow folds its children. The eye hides a 3D node. Right-click a node to add a child, attach a .ts script, rename it, or delete it. A new node is named after its type. A second one under the same parent is Name2. The inspector is where the type, position, rotation, visible flag, and script path are edited. Drop a node onto another to parent it. Save writes a .cscene file.

Another project is a folder under projects. The Project menu switches to it. Play in the editor works like Godot's: it saves the open scene and runs it in the game window, sized from project.corbel.json. The window locks its input: Space, Alt, and refresh belong to the game while the canvas holds focus (Devtools stays reachable with F12 or Ctrl+Shift+I/J/C), and Stop in the editor closes it. The 3D view stays the editing view; script errors from the window print on the window itself.

What it is

Corbel is an HTML5 creation engine. Games run on it. The future VoxiTect editor runs on it. You write TypeScript. The names of the types and methods follow Godot 4, so a script can move between GDScript and Corbel with small edits.

React is for panels, menus, and the site page. The scene tree owns the nodes. The class reference is documentation.html.

What you can do today

Math, the scene tree, and drawing are in @corbel/core. A canvas draws MeshInstance3D cubes through a Camera3D, lit by a DirectionalLight3D: WebGPU when the browser has it, WebGL2 otherwise. You cannot pick a voxel yet. The class list is documentation.html.

Four commands, from the Corbel folder:

npm run check
npm test
npm run try
npm run sandbox

check finds typos. test checks that the math and the scene tree still match Godot. try runs the file you are editing. sandbox opens http://127.0.0.1:5178/, where a box turns in 3D and the sidebar names the renderer. Add ?backend=webgl2 to that address to force the fallback.

The file you edit

packages/try/src/main.ts already contains this:

import { Vector3 } from "@corbel/core";

const forward = Vector3.FORWARD;

console.log("Corbel try file is running.");
console.log("Vector3.FORWARD is", forward.x, forward.y, forward.z);

Change it, save, then npm run check and npm run try. A character facing the camera looks like this:

import { Transform3D, Vector3 } from "@corbel/core";

const camera_pos = new Vector3(0, 1.5, 4);
const facing = Transform3D.IDENTITY.looking_at(camera_pos, Vector3.UP, true);

The world is Y-up and right-handed. Vector3.FORWARD is (0, 0, -1). A camera looks down -Z. A character that faces the camera looks toward +Z. Pass true as the third argument of looking_at for that facing.

Where GDScript and Corbel differ

TypeScript has no + for these types. A method does the same job.

// GDScript
var mid := a.lerp(b, 0.5)
var sum := a + b
var scaled := a * 2.0

// Corbel
const mid = a.lerp(b, 0.5);
const sum = a.add(b);
const scaled = a.mul(2);

The method names that already match are unchanged: length(), normalized(), dot(), cross(), lerp(), distance_to().

In 2D, Godot's Y points down the screen. Vector2.UP is (0, -1). In 3D, Y points up. Vector3.UP is (0, 1, 0).

Colors, cells, and the ground

import { AABB, Color, Plane, Vector3, Vector3i } from "@corbel/core";

const orange = Color.html("#ff8000");
const cell = new Vector3i(2, 0, -1);
const above = cell.add(Vector3i.UP);

const ground = new Plane(Vector3.UP, 0);
const hit = ground.intersects_ray(new Vector3(1, 2, 3), new Vector3(0, -1, 0));
// hit is (1, 0, 3). A ray that points away comes back null.

const box = new AABB(new Vector3(0, 0, 0), new Vector3(2, 2, 2));
box.has_point(box.get_center());

Vector3i truncates toward zero. A voxel cell will be one of these. The volume that stores cells is not written yet.

Build a mesh in code

SurfaceTool builds a mesh with triangles, vertices, normals, vertex colors, UVs, and tangents, and hands back an ArrayMesh any MeshInstance3D can draw. It is the Godot SurfaceTool flow: begin, set attributes, add a vertex, repeat, then commit. Attributes reset after every vertex, like Godot.

import { Color, MeshInstance3D, PrimitiveType, SurfaceTool, Vector2, Vector3 } from "@corbel/core";

const tool = new SurfaceTool();
tool.begin(PrimitiveType.TRIANGLES);
tool.set_uv(new Vector2(0.5, 0));
tool.set_color(Color.html("#22c55e"));
tool.add_vertex(new Vector3(0, 1, 0));    // apex
tool.add_vertex(new Vector3(-1, 0, 1));   // base left
tool.add_vertex(new Vector3(1, 0, 1));    // base right
tool.generate_normals();
const body = new MeshInstance3D();
body.geometry = tool.commit();

index() merges vertices that are the same, generate_normals() smooths face normals, and generate_tangents() fills the tangent from UVs. The class list is documentation.html.

Input and key binds

An action is a name a script reads, so a script can move between keyboard layouts and devices without edits. It works the way Godot's Input Map works, and the editor's dialog works like Godot's too: Project → Project settings… opens the Input Map. Type a name into Add New Action and press + Add, then press the action's + button to open the Event Configuration popup: type into Filter by Event, click the key (Keyboard Keys) or mouse button (Mouse Buttons), tick Additional Options (Alt, Shift, Ctrl, Windows) when they must be held along with it, and pick Physical Keycode (the key's position on a US QWERTY keyboard, layout-independent — Godot's default) or Keycode (what the current keyboard layout produces — auto-detected). The list shows binds Godot-style, like Space (Physical), with edit and delete buttons; each action also carries a Deadzone for later analog inputs.

import { Input, Node3D } from "@corbel/core";

export default class Player extends Node3D {
  override _process(delta: number): void {
    if (Input.is_action_pressed("move_forward")) {
      this.position.z -= delta * 2.0;
    }
  }
}

In the running game the canvas takes keyboard focus, so click the canvas once before playing with the keyboard. Input.is_action_just_pressed is true for the one frame a key went down; Input.is_key_pressed(Key.W) reads the raw key, and Key constants match Godot 4. A script class can also override _input(event) to see every event, key and mouse, in tree order.

Write a material's shader

A Shader is one program pair: the WGSL body runs on WebGPU and the GLSL body runs on WebGL2. Both bodies see the same names — color, normal, albedo, the light (light_dir, light_color, ambient, and a lighting() helper), and your own uniforms. Parameters are vec4, so a Color, a Vector3, and a single number all pass through set_shader_parameter.

import { Color, ShaderMaterial, Shader } from "@corbel/core";

const shader = Shader.lit({
  uniforms: ["Tint"],
  webgpu_body: "  return vec4f(albedo * color * lighting(normal) * Tint.rgb, 1.0);",
  webgl_body: "  return vec4(albedo * color * lighting() * Tint.rgb, 1.0);",
});
const material = new ShaderMaterial(shader);
material.set_shader_parameter("Tint", Color.html("#eab308"));
body.material_override = material; // the MeshInstance3D draws with it

Change the parameter and the next frame shows it. The same names work on both backends, so a machine on WebGL2 does not lose the effect.

Dictionaries and variables

TypeScript has no var-style untyped values here; use const and let. The Godot simple types map this way: int and float are number, bool is boolean, String is string, Array is an array, and Dictionary is the Dictionary class in @corbel/core: a key/value map kept in the order you set it.

import { Dictionary } from "@corbel/core";

const stats = new Dictionary();
stats.set("hp", 100);
stats.get_or_add("mp", 50);

const enemy = new Dictionary();
enemy.set("name", "Slime");
enemy.set("colors", ["green", "red"]);
enemy.merge(stats, true);        // overwrite the "hp" it finds
enemy.erase("mp");
const deep = enemy.duplicate(true); // nested dictionaries and arrays copied

has(key), get(key, fallback), keys(), values(), merge(other, overwrite), duplicate(deep), find_key(value), and erase(key) are there. The full class list is documentation.html.
